# Day1：进程与内存

> 目标：会查进程（谁在跑、什么状态）、会看内存（够不够、谁在吃）、会管进程（结束它）
> 评分：96/100（唯一扣分：ps aux 的 x 解释成"目录"）

## 1. ps —— 进程快照（点名册）

```bash
ps aux                          # 最常用：所有用户、详细、含无终端进程
ps -ef                          # 标准格式（Linux 系通用）
ps aux | grep nginx             # 找特定进程
```

| 字母 | 含义 |
|------|------|
| a | 所有**用户**的进程 |
| u | 详细**格式**（显示用户、资源） |
| x | 含**无终端**的进程（守护进程，TTY 列显示 `?`） |

重点列：`PID`（进程号）、`STAT`（状态）、`RSS`（实际内存 KB）、`COMMAND`（命令）。

💡 **记忆**：a = 所有用户，u = 详细格式，x = 无终端的后台进程（TTY 列是 `?`）。

⚠️ **易错点**：`ps aux | grep xxx` 结果里**永远有一行 grep 自己**（它的命令行含关键字）。排除：`| grep -v grep`，或直接用 `pgrep xxx`。

## 2. 进程状态 STAT

| 状态 | 含义 | 类比 |
|------|------|------|
| R | 运行中 | 正在干活 |
| S | 睡眠（等事件） | 睡觉等闹钟，正常 |
| D | 不可中断（卡 IO） | 在厕所出不来 ⚠️ |
| Z | 僵尸（父进程没回收） | 死了没人收尸 ⚠️ |
| T | 停止 | 被 Ctrl-Z 或 kill -STOP |

💡 **记忆**：Z 僵尸**杀不死**（kill 无效，它已经死了）——要处理它的**父进程**（PPID），父进程死后僵尸被 init/systemd 自动回收。

```bash
# 找僵尸
ps aux | awk '$8 ~ /Z/'
# 看僵尸的父进程（PPID 列）
ps -o pid,ppid,stat,cmd -p <僵尸PID>
```

## 3. top —— 动态监控（实时大屏）

```bash
top
```

| 键 | 作用 |
|----|------|
| P | 按 CPU 排序 |
| M | 按内存排序 |
| q | 退出 |

第一行 `load average: 0.10, 0.20, 0.15` = 1/5/15 分钟负载；1 核机器 >1 就偏忙。

## 4. free —— 内存（钱包余额）

```bash
free -h
```

```
              total   used   free   available
Mem:          1.6Gi   732Mi  93Mi   709Mi
```

**判断标准看 `available`**（free + 可回收的 cache）。`used` 高不一定是坏事——Linux 把空闲内存拿去做缓存（可随时回收），所以 `free` 低 ≠ 内存不够。

⚠️ **易错点**：新手看 `free` 列低就慌——`available` 才是"真正还能花的钱"。

## 5. kill —— 结束进程（裁员）

```bash
kill 1234              # SIGTERM(15)：礼貌请求退出（给时间保存/清理）
kill -9 1234           # SIGKILL(9)：强制杀死，无法拒绝
kill -l                # 列出所有信号
```

⚠️ **易错点**：**先 15 后 9**——能优雅退出就别强杀（9 会跳过清理逻辑，可能丢数据）。

## 6. 后台任务管理

```bash
sleep 300 &            # & 放后台跑，立即回到提示符
jobs                   # 查看后台任务：[1]+ Running sleep 300 &
fg %1                  # 拉回前台（%1 = jobs 编号）
bg %1                  # 恢复后台运行
nohup sleep 300 &      # 防 SSH 断开被杀（no hangup，免疫挂断信号）
kill %1                # 按任务编号结束
```

💡 **记忆**：`&` 防"占着终端"，`nohup` 防"断开被杀"。服务器跑长任务标准姿势：`nohup 命令 > 日志.log 2>&1 &`

⚠️ **易错点**：`nohup` 默认把输出写进 `nohup.out`（不是报错）；`Ctrl-Z` 是**挂起**不是退出（`fg` 恢复 / `kill %1` 干掉）；退出 SSH 用 `exit` 或 Ctrl-D。

## 7. 端口排查

```bash
ss -tlnp        # -t TCP -l 监听 -n 不解析 -p 进程

```

## 8. 实战：完整流程（Day1 实操记录）

```bash
# ① 启动后台任务
sleep 300 &
# [1] 9887

# ② 定位
ps aux | grep sleep
# root 9887 ... S 16:47 0:00 sleep 300
# root 9899 ... grep --color=auto sleep   ← 这是 grep 自己

# ③ 击杀
kill 9887
# [1]+  Terminated    sleep 300

# ④ 验证（第二次只剩 grep 自己 = 成功）
ps aux | grep sleep
```

服务器实测发现：mysqld 占内存 22.7% / 365Mi（1核2G 上 MySQL 是重服务，不必要别多开）。
